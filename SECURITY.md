# Security policy

Please report vulnerabilities privately through GitHub's **Security → Report a vulnerability** flow. Do not open a public issue for an unpatched vulnerability.

Security fixes are applied to the latest release line and `main`. This project
does not currently promise security maintenance for older container tags. Avoid
the rolling `latest` tag when your deployment requires controlled updates; pin a
version and review new releases before upgrading.

The bridge requires a Jellyfin administrator API key because Jellyfin restricts item metadata and user policy updates to administrators. Keep the service on a trusted network and use different long random values for `WEBHOOK_TOKEN` and `ADMIN_TOKEN`. JellyPass has two listeners: the admin listener (`ADMIN_HOST`:`ADMIN_PORT`, `127.0.0.1:8788` by default) serves the admin site and API, metrics, the Seerr webhook and health, and should be reachable only from this machine or a private network (expose only the webhook endpoint through a TLS reverse proxy if Seerr is on another network); the member listener (`HOST`:`PORT`) serves household addresses only and answers a `Host` that is no household's with a fixed `421`, never the admin site. `ADMIN_TOKEN` protects grant inspection, dry runs, group management, revocation, reconciliation, and metrics. It falls back to `WEBHOOK_TOKEN` only for backward compatibility.

Browser administration accepts only enabled Jellyfin administrator accounts. Credentials are sent directly to the configured Jellyfin server, are never stored or logged, and the temporary Jellyfin access token is logged out immediately after authentication. JellyPass then uses a random in-memory session. Session cookies are HttpOnly and SameSite=Strict; when the request arrives through an HTTPS reverse proxy they are Secure and named with the `__Host-` prefix, so sibling hosts under the same site cannot set them. Each session's administrator is re-read from Jellyfin every five minutes, and a deleted, demoted or disabled administrator's session ends. State-changing requests made with the session cookie, and sign-ins, must come from the admin origin (`Sec-Fetch-Site: same-origin`, or an `Origin` matching `Host`; `X-Forwarded-Host` is never trusted), checked before the session is, and request bodies must be declared as JSON, because `SameSite=Strict` does not stop requests from sibling hosts such as household hosts or Seerr. Failed web logins all get the same answer after at least one second, and are rate-limited per client address (the real client behind a trusted proxy) and per name from one address, with the same fixed `429` after the same second; failures for a name from many addresses only slow its sign-ins down (up to five seconds) and never lock its owner out. The admin listener has no gate of its own beyond the sign-in: keep it private, and if you proxy it, put it behind Cloudflare Access, a VPN or an allowlist. The service never logs passwords, Jellyfin access tokens, the Jellyfin API key, or webhook tokens. Its state file contains Jellyfin user identifiers and a catalog of media names and identifiers, and is created with owner-only permissions where the host filesystem supports them.

Household addresses are chosen from the request's `Host` alone, by exact match against the address map (and the legacy `HOUSEHOLD_DOMAIN` rule); `X-Forwarded-Host` is never read. A token is accepted on a household's address only for that household's members, so a valid token for another household gets the same `401` as an unknown one. Knowing an address is not authentication: anyone who can reach it sees that household's sign-in page. While the household gateway is on, `TRUSTED_PROXIES` is required, and household privacy holds only if members cannot reach Jellyfin or Seerr directly.
